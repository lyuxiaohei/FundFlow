# 投资项目管理系统（项目库）— 原始需求记录

> 本文件逐字收录需求提出方的原始表述，作为后续需求分析与方案设计的基准输入，防止推导过程中需求失真。
>
> 需求来源共两轮：① 首轮转述（见第一节）；② **2026-08-26 投资部需求沟通会**（转写稿：`./99-归档/2026-08-26 投资项目管理需求沟通/`，细化结论见第五节）。

## 一、需求原文（首轮提出）

> "另外，你们技术那边帮我们投资开发个系统来使用呗，算是项目库，我希望的是我们一接触到项目，哪怕收了个BP，就丢进去，然后记录放弃的时间节点，比如是看了BP就觉得没价值、不看，还是听了对方路演后，还是去公司访谈后，还是收到全部尽调资料后，还是立项会的时候，还是投决的时候，记录不投的原因。这是没投的。投了的要有全部投后管理的内容记录，直至清算、注销基金为止。"

## 二、提出背景

- 提出方：投资部（业务方），向技术方提出系统开发诉求；
- 系统定位：投资部自用的**项目库**——投资项目全生命周期记录与管理系统；
- 同期背景：技术方正在推进「AI 知识库」项目（见 `项目 01《P1-R01-方案分析报告》（5-【ACTIVE】AI知识库）`），两个项目同属投资部信息化建设；
- **基金背景**（2026-08-25 补充检索）：投资部所管理基金为**宏兆集团**旗下基金。宏兆集团 1995 年创立、总部深圳，业务聚焦股权投资基金管理、数字化供应链平台"一兆链采"与软件信息技术服务；核心投资平台为**深圳前海宏兆基金管理有限公司**（2014 年成立，股权/创业投资类私募基金管理人，总部深圳大湾区，于纽约、北京、上海设分支），聚焦**科技**（新一代信息技术、智能制造、半导体、AI、新能源、新材料）与**医疗大健康**两大赛道，业务含基金管理、直接投资、私有化退市、境外上市、上市公司定增，集团层面正探索航天、医疗、机器人等前沿方向。该背景对系统的含义：多分支机构的账号与权限体系、跨境业务（境外上市/私有化退市）的项目类型、多基金-项目关联（Q7）均应在设计中预留（信息来源：宏兆集团官网及公开工商信息）。

## 三、原文要点拆解

| # | 要点 | 含义 |
|---|---|---|
| R1 | 哪怕收了个 BP 就丢进去 | **最低入库门槛**：一接触项目即建档，不设筛选前置条件 |
| R2 | 记录放弃的时间节点 | 未投项目需标记**放弃时所处的阶段**（含时间戳） |
| R3 | 放弃节点选项：看BP觉得没价值不看 / 路演后 / 公司访谈后 / 收到全部尽调资料后 / 立项会时 / 投决时 | 原文给出了 6 个放弃节点的初始清单，即投前管道（项目十阶段）的雏形 |
| R4 | 记录不投的原因 | 放弃须附**原因**（2026-08-25 Q5 已确认结构化口径：预置分类选项 + 允许自定义补充，预置清单待业务提供） |
| R5 | 投了的要有全部投后管理的内容记录 | 已投项目进入**投后管理**，全量记录 |
| R6 | 直至清算、注销基金为止 | 生命周期终态为**基金清算/注销**——系统须覆盖到基金维度终局，而非仅项目退出 |

## 五、需求细化（2026-08-26 投资部需求沟通会）

> 依据同日沟通会转写稿整理，按主题归纳；时间点为转写稿标注。本节为原始需求（R1~R6）之后的**细化与扩展**，与第三节拆解并存，主报告/附件4/附件6 随后按此修订。

### 5.1 阶段管道修订（十阶段 → 十二阶段）

全周期状态刚性固化（01:01、29:55）：

```
① 接触/收 BP ──→ ② 线上路演 ──→ ③ 保密协议签署 ──→ ④ 尽调资料包 / 现场访谈
> ⚠️ 08-27 调整：⑧⑨ 已对调（先设立后出资），最新口径见《P2-R01-A01-需求调整记录-20260827》。
──→ ⑤ 立项 ──→ ⑥ 投资人路演（新增节点）──→ ⑦ 投决 ──→ ⑧ 出资
──→ ⑨ 基金设立（显式入链）──→ ⑩ 投后管理 ──→ ⑪ 项目退出 ──→ ⑫ 基金清算注销（终态）
```

- **④ 两条路径**（01:01）：签保密协议后对方直接发资料包（信任度高的）；或要求先现场访谈、确认跟进后再发资料包；
- **放弃节点由 6 个扩为 7 个**（覆盖①②④⑤⑥⑦ 共 7 个节点，③保密协议签署环节无放弃点；新增"投资人路演后放弃"）；
- 标准状态标签（出自转写稿"通用摘要"段，无逐字原文对应）：BP接收 / 路演完成 / 保密协议签署 / 尽调启动 / 立项通过 / 投决通过 / 已出资 / 投后管理 / 已退出 / 已注销，支持按放弃原因快速筛选统计。

### 5.2 放弃原因实例库（Q5 预置清单初始素材，01:38~03:55）

| 放弃节点 | 原因实例（转写稿原意） |
|---|---|
| 看 BP 后不看 | 明显超出投资范围 |
| 线上路演后 | 专业问题/同行情况答不出，逻辑薄弱，项目质量或团队能力不足 |
| 现场访谈后 | 工厂萧条、订单匮乏 |
| 收到尽调资料后 | 财务数据重大偏差、疑似造假 |
| 立项时（老板否决） | 创始人信用风险、人品问题、债务纠纷 |
| 投资人路演后 | 全体投资人明确不出资 |
| 投决时 | 估值未谈拢（如要求打折未成）、对赌条款设置不合理 |

### 5.3 基金与 LP（Q7/Q11 细化，05:13~06:18、30:04~36:23）

- **基金实体字段**：有限合伙全称、注册资本、成立日期、注册地、LPA/工商注册文件上传；
- **基金管理模块**：现有 CRM 无基金管理、纯线下管——新系统需要；出资记录按基金维度手工维护；
- **LP 管理（极简）**：LP 主体名称、认缴/实缴金额（如一千万/五千万）、出资时间文字录入；一个 LP 有多个主体；LP 资质材料（LPA 协议、主管协议、募集协议）上传归档；用途：内部备案与投资者资格认定；
- **项目不可跨基金复用**；已投项目独立归档：LP 协议、工商注册文件、托管协议、证券账户开立凭证等全部法律与运营文件（03:55）。

### 5.4 投后管理四项刚性功能（25:05、29:55~37:14）

1. **事件记录**：股东会/董事会决议、重大经营变动、定期访谈纪要——不强制细分类型，须支持附件上传与时间戳固化；
2. **报告归档**：季度/年度投后报告 + 专项报告（上市减持、清算报告等），允许手动上传；
3. **风险预警**：监控已投企业二级市场股价走势、行业舆情（指定网站定时收集汇总、定期推送，可接企查查/同花顺等）；
4. **到期提醒**：对赌协议到期、回购触发、关键条款履约/资质续期等，**前置 ≥30 天**系统提醒。

V2 取舍（28:01~29:03）：风险预警与到期提醒点亮纳入；**财报自动收集（手动上传即可）、委派董事管理、尽调模板（20:33~20:40，尽调以向公司索取资料包 + 现场访谈为主）确认不做**。

### 5.5 退出三段递进（31:47~33:43，不可合并或省略）

1. **项目退出**（"退出登记"改名）：大类统一入口，退出类型表单内选择——分红 / 股权转让 / IPO 减持等；支持**分批次登记**；字段：卖出价格与数量、时间节点、退出本金、收益、收益率；
2. **收益分配**：承接退出资金，按 LP 约定比例核算、LP 分配明细及时间节点（含付款记录）；
3. **基金清算注销**：专项基金所投项目**全部退出后**启动——清算报告生成、资产处置、税务清算、剩余资金分配、工商注销，基金层面终局闭环。（该模块归入投后管理还是基金管理**待定**，32:41~32:55）

### 5.6 材料归档规则（12:39~17:42，治现有 CRM 痛点）

- 按逻辑包**强制分类**：BP 包 / 路演纪要 / 尽调资料包 / 投决包 / 基金设立文件 / 投后资料，替代现有"通用附件堆砌"；
- 现有 CRM 三大缺陷（重建动因）：附件不分类、项目管理/投后管理/投资跟进三模块职责重叠、已投项目混入投前池导致状态不清。

### 5.7 系统边界及其它（06:55~08:53、34:05~35:06）

- **不与财务/OA/外部监管系统打通**，仅内部项目台账；关键投后数据以字段录入（退出时点、价格数量、本金/收益/收益率、LP 分配明细、清算报告触发）；
- **内置在线审批**：立项申请、投决上会、付款指令、基金设立备案、退出决策；可独立运行，也可嵌入 OA「投资产业」板块下"投资项目管理"文件夹（立项/投决/基金注册/付款/分配/注销六节点；现有 OA 实为**简道云**，07:26，转写稿 ASR 误作"剪刀云"）；
- **智能协同**：WorkBuddy（沃八里；转写稿中名称音译不稳定——WorkBari/沃八里/沃money里等，归一为 WorkBuddy）自然语言调用项目库、触发尽调指令/舆情检索，联动企查查等（对应主报告第六节 MCP 协同机制）；
- **机构管理模块暂缓**（无实际使用需求）；权限统一角色 + 菜单级控制；统计报表（漏斗/放弃率）先上系统再定（现为半年/年度手工统计）；
- **待办**：嘉怡与胡博对接，细化功能菜单/字段定义/原型；胡博牵头协同陈有、华悦确认基金设立与投后模块字段与流程细节；向华悦同步投后四模块业务规则。
